# One-day economic event study around the fourth-quadrant unlock

## Outcome
Explain *when* and *how* the economic trajectories diverge in daily Kaggriculture replays when one seat unlocks its fourth quadrant and the opponent does not. This is research for a future adaptive agent, **not** an agent change, leaderboard optimisation, or a causal claim that buying land alone wins games.

## Scope and constraints
- Run the full-scale analysis **on Kaggle**, where daily replay datasets are mounted. Never download a daily dataset to the workstation.
- Attach and process **exactly one daily episode dataset per notebook run**; fail before replay parsing if zero or more than one daily source is mounted. Index, engine tables, reference agents and competition sources are not daily episode datasets. Start with 2026-09-24, then run 2026-09-23 separately as a replication. Do not pool the runs into a single causal estimate.
- The current Lab metadata attaches nine days and Tier 2 round-robins them: never push it unchanged. Preserve the generated-notebook workflow (`kaggle/lab/build_notebook.py` -> `kaggriculture-lab.ipynb`).
- Make no changes to submitted agents, submissions, or Kaggle competition entries. Do not commit unless the user explicitly asks.
- Keep full replays off transcript and local disk. Print bounded daily/event-time summaries and coverage; if needed, store small tables in `/kaggle/working`.

## Measurement contract
1. Unit of comparison: **the two seats of the same replay**; the primary cohort has exactly one seat reaching four quadrants and its opponent staying at three. Report the number of matches, distinct teams and dataset date. Other configurations are described separately, not mixed into the main cohort.
2. Treatment timestamp: the **observed** transition in `farm.unlocked_quadrants` from 3 to 4. `BUY_LAND` is merely a request and can silently fail. Use the replay action/observation offset proven in `replay_opponent.py`; unit-test around the purchase and the day boundary.
3. Daily snapshots: final observed cash (`farm.money`) for each in-game day, its change from the prior day, and buyer-minus-opponent cash gap. A purchase mechanically removes $4,000; label that day separately. Also record observable crop/structure occupancy, animal count, hires, shed/worker holdings and product flow where attribution is reliable. Do not report requested market units as executed sales or label net cash change "revenue".
4. Display both calendar-day series (days 0–29) and event-time series relative to the buyer's unlock day (e.g. −4..+8). Show pre-purchase trend, purchase-day dip, time to recover the prior gap, and final margin and win share. Report denominators at every day/event offset, missing snapshots/skips and reasons; never silently reduce the sample.
5. Stratify by dataset publication date (one run/day). A within-game control removes common shop/market/seed conditions but **not** policy, skill or selection effects; day 10 also brings first strawberry/melon yield. Any pre/post or difference-in-differences column is descriptive, not causal. Repeated teams mean replay rows are not independent people.
